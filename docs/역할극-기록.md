# 역할극 기록 — 스킬을 고친 근거

스킬을 고칠 때마다 새 세션을 디자이너로, 메인 세션을 의뢰인(사장님)으로 두고 시안을 끝까지 만들어 본다. 의뢰인이 짚기 전에 디자이너가 먼저 했는지, 같은 틀로 나오지 않았는지, 토큰이 어디서 드는지를 본다.

`<역할극 폴더>` 는 역할극 자료를 모으는 내 컴퓨터의 폴더(저장소 밖)다. 아래에 시안\·사진\·비교\ 를 둔다.

## 하는 법

0. 역할극 자료(시안·사진)는 `<역할극 폴더>\시안\`·`<역할극 폴더>\사진\` 에 모은다. 진행 중인 것만 그 위 폴더에 두고 끝나면 옮긴다.
1. 사장님 사진: 한 가게를 한 사람이 같은 날 찍은, 상업 이용 되는 사진(위키미디어 공용 CC0 등)을 `<역할극 폴더>\사진\사장님-사진-<업종>\` 에 받고 `출처.md` 에 사진마다 사람·남의 간판·전화번호·값표를 적는다.
2. 사장님 역할 메모(메뉴·값·쉬는 날·채널·싫은 것·사진 속 누구 것)를 먼저 써 두고, 묻는 것에만 같은 말로 답한다.
3. 새 세션에 `/ui-design-director <가게> 홈페이지. 의뢰인은 사장님(메인 세션, 역할극 — 답은 SendMessage). 프로젝트 폴더: … 사장님 사진: …` 를 붙인다.
4. 디자이너 메시지를 받을 때마다 구간 줄을 `docs/roleplay-phases/<이름>.txt` 에 더하고, 끝나면 `python -X utf8 scripts/roleplay_tokens.py <세션 ID> <구간 파일>` 로 센다.
5. 아니다 싶으면(같은 틀, 토큰이 지난번을 따라감) 중간에 멈추고 원인부터 고친다.

## 반복 시험(2026-11-06부터, 사용자 지시)

디자인이 좋아질 때까지 주제와 의뢰인 역할을 바꿔 가며 역할극을 되풀이하고, 매번 스킬·규칙을 고친다.
- 의뢰인은 **메인 페이지만** 요청한다(SKILL § Main page recipe). 다 만들지 않는다.
- 목표: 참고 사이트의 디자인을 따르되 베낀 티가 나지 않게. 스킬 없이 만든 것보다 나아야 한다.
- 메인 페이지 index 가 어느 정도 나오면 멈추고 사용자에게 경로를 알려 판별을 받는다. 판별 전에는 「됐다」고 하지 않는다.
- 토큰: 회차마다 `roleplay_tokens.py` 로 재고, 메인 페이지까지 80번 안쪽을 목표로 한다.
- 회차마다 이 문서 표에 한 줄, 고친 것은 「배운 것」에 한 줄.

## 배운 것

### 같은 틀·바탕 따르기

- **같은 틀은 규칙이 만든다.** 카페·분식집 1차가 참고가 달라도 같은 부품으로 나왔다 — AI 티를 피하려던 「이렇게 하라」 규칙이 정답 틀이 됐다. → 규칙은 금지만, 부품은 이번 참고(n/N)와 가게 물건에서(`DESIGN.md` § 부품 출처).
- **공통점만으로는 평균 웹사이트가 나온다(깡통구제).** 여러 사이트의 공통 숫자는 어느 업종이든 같고, 한 곳만의 생김새를 지우니 모델 기본값이 채웠다. 사용자 정정: 고른 바탕을 따르고 공통점이 있는 곳만 다르게 → `skeleton.mjs --base`, preflight 「바탕 빠짐」.
- **바탕 하나를 고르게 하니 바탕을 닮았다(5차).** Amsterdam Light Festival 을 고르자 검은 바탕·분홍 칸·알약 단추로 나왔고 흰 바탕·가는 선으로 돌아가지 않았다. 참고 모으기 36번(4차 88번).
- **유명 서비스를 바탕으로 고르면 짜임은 그 서비스다(6차).** 당근 바탕에서 주황을 빼고 동 표시·만날 곳으로 바꿨지만, 배치를 「당근 웹과 같은 방식」이라고 의뢰인에게 그대로 설명했다. 진행자가 메모에 없는 말을 덧붙인 것은 감안(→ SKILL § Before each message 4).
- **스킬 없이 만든 것과 같았다(6차 뒤).** 스킬 없는 하위 에이전트의 첫 화면과 짜임이 같고 색만 달랐다. 원인: 지운 얼굴 자리를 채우라는 말이 없고 점검이 「닮았나」만 쟀다. → Quality bar 「스킬 없는 결과와 비교」. 그림: `<역할극 폴더>\비교\옆집마켓-캡처\`.
- **「너무 네모」는 모양이 아니라 쌓인 칸.** 모서리 0 → 둥근 사진 띠·알약 단추로 바꾸자 「네이버랑 똑같다」.
- **진행자도 생김새를 봐야 한다.** 배치 셋을 「짜임이 다르다」고 넘겼는데 순서만 달랐다 — 사용자가 짚었다.
- **의뢰인은 지난 시안을 모른다.** 이전 프로젝트와 비교(`--prev`)는 스킬 시험용일 뿐이다(사용자 정정).

### 생성 티

- **사용자 판별 7차(캠핑장): AI 티는 규칙이 만들었다.** 사진 위 흰 정보 상자, 동그라미 글자 아이콘, 점선 「… 자리」 칸, 옅은 띠, 직사각형 남발 — 「특색을 첫 화면 앞에」·「표시한 빈칸」·「큰 면이 달라야」 규칙에서 나왔다. → 그 규칙을 빼고 상자 수는 바탕 이하, 견본 글은 아래 한 줄. 그림: `<역할극 폴더>\비교\솔숲캠핑장-캡처\`.
- **사용자 판별 8차(필라테스): 짜임은 따랐지만 마감이 AI 기본값.** 단색, 본문 글씨 이름, 흔한 검은 알약 단추, 프리텐다드·마루부리. 원인: 「검정 말고 강조색 하나」, 이름·단추 마감을 옮기라는 말 없음. → 바탕의 4~6색 조합, 이름·메뉴·단추 마감도 재서 옮김.
- **남의 생성 티 목록은 장식만 잡는다(unslop, 7차 다시).** 이모지·순서 표시·자간은 고쳤지만 사진 위 정보 상자·옅은 띠·빈칸·상자 수는 그대로였다. → 쓸 만한 항목(넓은 자간·이모지·빛·마우스 올리면 커짐·숫자 형식)만 build-rules·check_site 에 더함.
- **시안 장치가 기능을 가렸다(6차).** 시안용 「상태」 단추가 값·설명을, 붙은 아래 줄이 고치기·지우기를 가렸다 — 의뢰인이 짚었다. 보내기 전 점검에 「떠 있는 것이 무엇을 가리는가」가 없다.

### 글꼴

- **기억으로 고르면 늘 같았다(10차·재연).** 금지 목록이 시안 규칙에만 있고 팔레트 규칙과 틀 예시는 오히려 Wanted Sans·리디바탕을 들었다. 두 세션 모두 1·2위가 Pretendard·Wanted Sans. → 방문 상위 186곳 실측 + 눈누 회사·기관 공개 글꼴로 표(`assets/fonts/fonts.json`)를 만들고 `fonts.py pick` 으로만, AI 글꼴 17종은 preflight·훅이 막음.
- **AI 글꼴 모델 시험(2026-11-09).** 글꼴 지시 없이 24번 만들게 하니 Pretendard 12·Noto Sans KR 11, 목록 밖 웹 글꼴은 없었다 — 목록이 맞다(`ai-fonts.json` 근거).
- **디자인 지식은 데이터로 꺼내 본다(2026-11-09).** 무료 강의·글(자료 164곳, 디자이너 약 42명)을 규칙 731개로 꼬리표 달아 `knowledge.py` 가 부품·단계별로 몇 줄만, 숫자 규칙은 check_site 가 잰다.

### 보기 화면·도구

- **참고 사이트 보여 주기 — 우회만으로는 반(2026-11-06).** 틀 안 띄우기를 막는 50곳 중 우회로 원래 모습은 23곳. → 2배 캡처·실제 브라우저 이름·스냅샷·움직임 기록·실제 창 보기. 사람은 실제 사이트로 고르고 AI 는 잰 값으로 옮긴다. 결과: `<역할극 폴더>\비교\우회시험-50\`.
- **도구가 브라우저를 남겼다(2026-11-06).** 윈도우에서 `proc.kill()` 은 첫 프로세스만 꺼 Edge 본체가 남았고, 시간 초과로 죽은 도구는 끄지도 못했다(하루 75벌, 51GB). → `browser.mjs` 가 나무째 끄고, 남은 것은 다음 실행과 플러그인 훅이 치운다.
- **점검 도구는 실제 프로젝트에서 잘못 걸린다.** preflight 가 「인스타 없음」을 채널로 세고, 계획 전에 사장님 화면을 물었다 — 고친 뒤 `tests/` 에 그대로 옮겼다.

### 판별

- **판정자는 내용 바닥이 있다.** 2차도 컴퓨터 판정은 「만든 티 우세」 — 11년 전 사진, 가게 고유 글씨 없음. 사장님 점수는 실제 가게들 가운데였다.
- **디자이너는 스킬 저장소 밖에서 연다.** 저장소 폴더에서 열면 git 기록·메모리로 의뢰인 요청을 미리 안다. 진주 축제부터 `<역할극 폴더>\시안\<프로젝트>\` 에서 연다.
- **화면 상태는 먼저, 위험은 덜(6차).** 빈 목록·실패·예약 중·되돌리기 등은 묻기 전에 그렸지만, 사진 속 사람 다리, 동·호수 개인정보, 신고 단추, 팔면 안 되는 물건 안내는 끝까지 안 나왔다.
- **맥락의 목적이 페이지 목록에서 빠졌다(5차).** 처음 말한 먹거리·체험 부스·사진 모음이 페이지 목록 초안에 없었다 — 의뢰인이 짚었다. 계획 단계에서 목적을 페이지에 하나씩 맞춰 보는 점검이 없다.
- **같은 것을 세 번 묻지 말고 사장님이 고치게.** 맡김 날짜 셈법을 세 번 따로 물었다. 규칙 하나와 사장님 화면에서 날짜 바꾸기를 먼저 제안했어야.
